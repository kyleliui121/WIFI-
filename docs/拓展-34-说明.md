# 选做拓展 3、4 · 四类业务与 ns-3

## 四类业务

SimPy 把 VO、VI、BE、BK 分成四个接入类别。两个 VO 站与两个 VI 站每 10 ms 分别生成 100 B 和 1000 B 帧。其余站在 BE（1500 B）和 BK（500 B）间均分，每站保持一帧等待发送。实验比较 DCF 和 EDCA，在 N=10、20、30，种子 42、43、44 的配置下运行 18 组，每组 10 秒。另用 AIFSN=3、5、7 对 BK 做 18 组敏感性实验。

主信道逐帧判断能否在下一次外部忙期前发完，再对可发帧处理同站竞争。截止结果按观测窗统计，包括已经逾期且仍未完成的帧。BE/BK 无截止门限。基本矩阵每站一个 AC，同站多队列争用由独立测试覆盖。

N=10 时，VO 的成功帧平均时延从 DCF 的 11.92 ms 降到 EDCA 的 1.67 ms，截止已观测失败率从 21.15% 降到 0.90%。EDCA 下 BK 的低吞吐随站点数增加而加重。N=30 时，AIFSN 从 7 降到 3，BK 吞吐由约 0.37 增至 3.06 Mbit/s，同时 BE 由约 13.78 降至 7.82 Mbit/s。 [四类汇总](../data/extensions/34/ext4ac_summary.csv) · [敏感性原始数据](../data/extensions/34/ext4ac_bk_aifs_sensitivity.csv)

## ns-3 对照与报告

用 N=10、种子 42、10 秒测量窗，对齐干净信道的 DCF 与 EDCA。ns-3 设有 2 秒关联预热。两边保持相同应用帧负载和竞争窗口设置，ns-3 的时延止于 AP 收到应用帧，SimPy 的时延止于 ACK 完成。使用实际发出的 QoS TID 校验 ns-3 的分类。 [构建与运行](../ns3ext/README.md)

本次用 ns-3.49 重新编译并运行。共观察到 36,563 次 EDCA 数据发送，VO、VI、BE、BK 分别使用预期的 TID 6、4、0、1。DCF 的 SimPy 与 ns-3 总吞吐分别为 23.37、22.29 Mbit/s，EDCA 为 27.34、26.43 Mbit/s。EDCA 的 VO 平均时延为 0.74、0.78 ms，VI 为 1.22、1.28 ms。这个单种子对照展示了两种模型在该配置的表现。 [原始 ns-3 CSV](../data/extensions/34/ns3_crosscheck.csv) · [配对比较](../data/extensions/34/ext_ns3_comparison.csv) · [完整结果表](../data/extensions/34/ext4ac_tables.md)

Windows 完整报告使用 `python -m pip install -r requirements-report.txt` 安装依赖，双击 `run_ext34.bat` 后会生成 SimPy 实验、敏感性数据和报告。默认使用仓库归档的 ns-3 原始 CSV，也可把另一份同配置 CSV 作为批处理的第一个参数。
