# 选做拓展 1、2：帧错误率与隐藏终端

这两项拓展在当前必做仿真引擎上运行。两种扩展开关默认关闭。每次拓展运行都生成同一时长、同一站点数、同一方案和同一种子的对照组。

## 拓展 1 · 帧错误率

对每次无碰撞的数据帧尝试，以设定概率独立判定错误。错误帧按照失败、退避和重传处理。ACK 假定无错，ACK 等待采用与碰撞相同的时长近似。上限为 7 次重传，最多 8 次尝试。独立的错误随机流使用 `seed + 2_000_000`，每站退避流和外部占用日历沿用必做设置。

实验使用 1%、2.5%、5% 三档输入错误概率，共 108 组，并复用 36 组 0% 对照。CSV 的 `frame_error_pct` 以全部尝试为分母，`frame_error_given_no_collision_pct` 以无碰撞尝试为分母。重试耗尽的高优先级帧按最后一次失败原因归入错误或碰撞。

以 N=10 的 EDCA 为例，错误概率从 0% 增至 5% 时，低优先级吞吐从 17.39 降至 16.65 Mbit/s（约 4.3%），已观测截止失败率从 0.53% 升至 0.65%。成功帧 p99.9 在四档中为 14.70、15.27、13.41、15.13 ms。

## 拓展 2 · 隐藏终端

站点按 ID 的奇偶性分成两组，各自只侦听本组。外部占用仍同时约束两组，主信道发送仍按帧判断能否在下次邻网忙期前完成。不同组在同一信道上的传输重叠时，AP 判两组的帧失败。本模型把重叠发送的完成时刻都延至较长发送结束，用于同步两组碰撞后的退避。

共运行 36 组隐藏终端实验并与 36 组互听对照比较。模型省略 RTS/CTS、捕获效应以及隐藏站侦听 AP 的 ACK 或 Beacon。对照结果适用于这些简化假设。

N=10 时，隐藏场景下 DCF、EDCA、P-EDCA 和 NPCA 的高优先级成功率依次为 95.57%、31.02%、22.30% 和 20.07%。DCF 中仍有 41.57% 的截止已观测帧未能按时交付。EDCA 的成功帧 p99.9 从 14.70 降至 9.92 ms，同时丢弃率升至 68.98%。这些指标一起反映了成功样本被筛选后的时延分布。

## 统计与复现

p99.9 只统计成功发送的高优先级帧。引用隐藏终端结果时，同时报告成功率、已观测截止失败率、丢弃率和未完成率。两项选做均沿用[必做统计口径](methodology.md#5-统计口径务必保持一致)。

完整数据、表格与图均由当前代码按 10 秒、种子 42/43/44 重新生成。 [配置与代码哈希](../data/extensions/12/ext_metadata.json) · [实验结果表](../data/extensions/12/ext_tables.md) · [原包问题与接入记录](拓展-12-接入记录.md)

```bash
python -m wifi_sim.extensions --out results/extensions --duration 10 --seeds 42 43 44
python -m tools.analyze_extensions --results results/extensions
```

Windows 可双击 `run_extensions.bat` 完成同一流程。在 VS Code 中也可选择「跑选做拓展 1/2」生成数据和图，再运行汇总命令。
